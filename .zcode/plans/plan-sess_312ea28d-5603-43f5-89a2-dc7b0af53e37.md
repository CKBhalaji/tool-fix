## 3. Authentication (backend-only Firebase — the key design resolution)
Your spec forbids any Firebase SDK/config in the browser, so "Continue with Google" is a **server-side OAuth 2.0 authorization-code flow** (this is the only mechanism where the browser never touches Firebase/Google tokens):
1. Frontend button → navigates to `GET /api/v1/auth/google/login` (backend builds Google consent URL with state+PKCE from the OAuth client secret in `secrets/`).
2. Google redirects to `GET /api/v1/auth/google/callback` → server-to-server code exchange → verified Google identity.
3. Backend provisions/links the Firebase user via Firebase Identity Toolkit REST `signInWithIdp` (backend-only, uses `FIREBASE_WEB_API_KEY` — added to backend env; if absent in dev, skip with a warning and proceed on the verified Google identity).
4. Find/create ToolFix user (role derived server-side) → create `auth_sessions` row (hashed refresh) → set `access_token` + `refresh_token` HttpOnly cookies → 302 to `${FRONTEND_ORIGIN}/auth/callback`.
5. `POST /api/v1/auth/google` also implemented (returns the consent URL as JSON, per your §7 endpoint list). `POST /auth/refresh` rotates (reuse of a revoked token revokes the session); `POST /auth/logout` revokes + clears cookies; `GET /auth/me` from access cookie.
- **One-time user setup (documented in AUTHENTICATION.md + .env.example):** add `http://localhost:8080/api/v1/auth/google/callback` to the OAuth client's authorized redirect URIs in Google Cloud Console; put the Firebase Web API key in `backend/.env`.
- Dev note: `COOKIE_SECURE=false` locally; cookies work across localhost ports (same-site); CORS allows exactly `http://localhost:3000` with credentials.
